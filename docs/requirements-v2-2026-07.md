## 1. 目的・価値仮説（再検討）

**課題**: X 純正のブロック/ミュートでは、他人のリポスト・引用経由で対象アカウントの投稿がタイムラインに露出する。さらに 2024-11 の X 仕様変更でブロックが弱体化（ブロックされた側が公開投稿を閲覧可能に）し、「ブロックしても守られない」感覚がユーザー側で強まっている。

**価値仮説**: 「自分が既にブロック/ミュートした相手を、リポスト・引用経由でも見ずに済む」体験を、完全ローカル・追加操作ほぼゼロ（同期は設定ページを開いてスクロールするだけ）で提供する。配信画面にタイムラインを映す VTuber/配信者には、単なる快適さでなく**放送事故防止**の価値がある。

**利用者**:

- Primary: VTuber・配信者（ブロック/ミュートを多用し、画面共有時の露出が実害になる層）。
- Secondary: ブロック/ミュートを多用する一般ユーザー（誹謗中傷対策・ヘイト回避目的）。

**再検討の結論（Fable5 判断）**: 目的・対象ユーザー・完全ローカル方針は現行のまま妥当。X のブロック弱体化はむしろ本拡張の需要を裏付ける。ピボット不要。

## 2. 市場・競合（2026-07 時点）

詳細は `docs/research/market-2026-07.md`（Web 調査メモ）。要点:

- 課題（RT/引用経由のブロック・ミュート漏れ）は実在し、2024 年の X ブロック弱体化で悪化方向。市場は空白ではない。
- 直接競合は Control Panel for Twitter（約30万ユーザー・活発保守・引用経由の非表示機能あり・英語圏主体・多機能）と Badges: New Color（日本語圏・ニッチ）。Block Party / Megablock 等の API 依存系は X API 有料化で死滅済み。
- X 規約リスクは低いと推定（表示フィルタのみ・アクション実行なし・外部送信なし。同種大規模拡張の公開継続が傍証）。ただし名指しの許可規定は未確認。

**ポジショニング（相談役指摘 #7 反映）**: 多機能競争はしない。ただし「単機能・日本語・完全ローカル」は乗り換え理由としては弱いので、勝負する軸を明文化する — (a) **信頼**（権限 2 ホスト＋storage のみ・外部送信ゼロをストア文言で検証可能な形で示す）、(b) **初期設定の簡単さ**（同期はリンクを開いてスクロールするだけ）、(c) **配信者向けの事故防止**という用途特化訴求。既存 `docs/store-listing.md` はこの軸と整合しており、公開後の文言改善もこの 3 軸に沿って行う。

## 4. 非目標（確認）

- X API / OAuth 連携（F1-C は closed）。
- ブロック/ミュートの実行・解除の代行（本拡張は「表示フィルタのみ」）。
- 多ブラウザ対応（Firefox/Safari）・モバイル対応（現時点では非目標。要望次第で将来検討）。
- キーワードミュート・正規表現フィルタ等の汎用フィルタリング（single purpose 維持）。

## 5. UI の必要性再検討（popup / options / 警告）

Prompt addendum「拡張popup/設定/警告の必要性を再検討する」への回答:

- **popup: 必要・現行構成を維持**。①フィルタ ON/OFF＋表示モード3択、②同期導線（有効化→設定ページリンク→件数/最終同期）、③options への導線。非エンジニアが説明書なしで完結する動線として妥当。「ローカル確認用データ」セクションは dev フラグで出荷時非表示（確認済み）。
- **options: 必要・現行構成を維持**。プライバシー説明・フィルタ対象一覧の透明性表示・削除手段は、CWS のプライバシー要件（開示と削除手段）とも整合し、審査上も有利。
- **警告 UI: 審査中は実装しない。ただし仕様は今定義する**（相談役指摘 #8 反映）。同期（設定ページを開いてスクロール）は本拡張の中核体験であり、非エンジニアには案内が要る。v1.2 候補仕様:
  - 表示条件（案）: (1) フィルタ ON かつ同期件数 0（初回同期未完了）、(2) 最終同期から 30 日超。
  - 文言（案）: (1)「まだブロック・ミュート一覧を取り込んでいません。下のリンクから一覧を開いて、一番下までスクロールしてください。」／(2)「最後の同期から 30 日以上たっています。最近ブロック・ミュートした相手を反映するには、もう一度一覧を開いてください。」
  - 表示場所: popup 同期セクション内の注意行（新規画面は作らない）。エラー調にしない（ブランドトーン維持）。
  - 実装トリガ: 審査通過後、オーナーが v1.2 スコープを承認したとき（§9④ 要件変更ゲート）。

新規ビジュアル設計は不要（現行トークン準拠のまま）。よって ClaudeDesign ブリーフは本フェーズでは発行しない。
