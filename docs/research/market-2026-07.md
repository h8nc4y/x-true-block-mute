## 2. X 本体の仕様変化

- 2024-09〜10: X が「ブロックされた側も公開投稿を閲覧可能」へ仕様変更（TechCrunch / Forbes 報道）。純正ブロックの弱体化であり、本拡張の需要を裏付ける方向。
- 検索フィルタ（`include:nativeretweets` 等）使用時にブロック/ミュートが漏れるとの日本語圏報告あり（一次本文は未確認）。
- GraphQL 内部 API（doc_id 等）は高頻度で変更されるが、本拡張は API を叩かないため直接影響は受けにくい。**タイムライン DOM 構造変更によるセレクタ崩壊リスクは残る**（具体的な破壊事例の頻度は未確認）。`data-testid` ベースの現行実装と MutationObserver 追従が防御線。

## 3. 利用規約・自動化ポリシー上のリスク評価

- X の自動化ルールの主対象は「アカウントによるアクション自動実行」「非公式 API / スクレイピングによるデータ取得」。本拡張は表示フィルタのみ・アクション実行なし・外部送信なしで、これらに該当しない可能性が高い（推定）。
- ただし「表示フィルタのみのブラウザ拡張」を名指しで許可/禁止する一次記述は**未確認**。Control Panel for Twitter（30万ユーザー）が 2026 年時点で公開継続している事実が、同種アプローチが実務上黙認されている傍証。
- 結論: リスク低と推定（断定はしない）。

## 4. Chrome Web Store 審査動向（2025-2026）

- 公式: 「ほとんどの拡張は数日、数週間かかる場合もある。**保留 3 週間超なら Developer Support へ問い合わせ推奨**」（developer.chrome.com/docs/webstore/review-process）。
- **2026-04 時点で Google が提出急増による審査期間の延伸を公式告知**。本拡張は 2026-06-14 提出→ 2026-07-05 に 3 週間到達。
- 審査が厳しくなる要因: 広範な host_permissions（`<all_urls>` 等）。本拡張は 2 ホスト限定であり有利。
- `world:"MAIN"` content script / fetch・XHR フックを名指しで禁止する公式規定は未確認。ただし MV3 コード透明性要件（全機能がコードから判別可能・リモートコード禁止）の観点で人手レビュー対象になりやすい可能性（推定）。
- プライバシー要件: マニフェスト権限・ダッシュボードのデータ開示・プライバシーポリシー本文の三者突き合わせで矛盾があると却下。本拡張は `docs/privacy-policy.md|.html` と store-listing のデータ使用フォーム回答を整合済み（repo 内根拠）。
- 却下時: 理由メール→修正→再提出（回数制限なし、再審査は 1〜3 日との第三者情報）。アピールは同一違反につき原則 1 回。
- X/Twitter 対象拡張に特有の却下事例: 未確認（同種拡張が複数公開継続中）。

出典: developer.chrome.com（review-process / troubleshooting / user-data-faq / limited-use / mv3-requirements / program-policies）、extensionbooster.net（第三者解説）。

## 5. 市場規模の手がかり

- 同種最大の Control Panel for Twitter が約30万ユーザー。ニッチ特化（Ultimate Twitter Block）は 143 ユーザーに留まる例もあり、**告知・発見性が規模を左右**する。
- 日本語圏では「ブロック貫通」「ミュート漏れ」を扱う専門ブログ（PEKETTER TECH）が対策拡張を自作・配布するほどの需要と認知が存在。
- VTuber/配信者コミュニティ限定の定量データは未確認（2021 年の「地雷過多の Vtuber オタクによる自衛」匿名記事など質的シグナルのみ）。

## 6. 本プロダクトへの示唆（Fable5 総合判断）

1. 需要は実在し、X のブロック弱体化（2024）で強まる方向。ピボット不要。
2. Control Panel for Twitter と全面的な機能競争はしない。勝負軸は「信頼（最小権限・外部送信ゼロ）」「初期設定の簡単さ」「配信者向け事故防止」の 3 つ（`docs/requirements-v2-2026-07.md` §2。現 store-listing と整合）。
3. 審査待ちが 3 週間に達する 2026-07-05 が行動トリガー。オーナーのダッシュボード確認＋必要ならサポート問い合わせ（`docs/review-response-playbook.md` §1）。
4. 公開後リスクは 2 系統に分けて扱う: **同期取り込み破損**（X の設定ページ応答形状変更）と**タイムライン表示フィルタ破損**（DOM 構造変更）。検知・対応は `docs/requirements-v2-2026-07.md` §9 と playbook §3。
